# 易理明灯 · 对话与知识库完整方案 v3（用户确认版）

> 用户 8/8 明确：**豆包式对话是贯穿始终的基调**，检索是可选增强；无场景预设；查不到时上下文+系统引导传给模型自然对话。

## 一、核心定位（产品视角）

**用户为什么找我们，而不是直接找大模型？**
- 大模型（豆包/ChatGPT）给的是**通用回答**——它不懂命理
- 我们 = **豆包级对话体验**（自然、有温度、接住情绪）+ **276 万古籍知识库**（专业、有依据）
- 同样一个问题，用户在我们这得到的是**既有对话温度、又有专业依据**的回答——这就是差异化

**产品形态（用户无感）**：
- 用户感知到的永远是：**和一位懂命理的温暖朋友聊天**
- 知识库在**幕后默默工作**（像豆包的联网/知识增强一样）：AI 回答时自己决定要不要"查一下资料"，查到就用资料把回答讲得更专业更准；查不到就基于通用能力和对话上下文自然回答——**用户全程感知不到"检索"这件事**
- 系统不做"查到/查不到"的两段式——**只有一种模式：豆包式对话**，知识库只是让回答更专业的幕后助手

**四层黑盒（对标豆包/Kimi 流畅体验）**：
```
用户层：对话式交互 · 流式输出 · 语音文字无缝切换（体验丝滑）
应用层：知识库增强在后台默默工作（用户无感）
模型层：LLM 自主判断（意图/情绪/工具）
基础设施层：性能（3 秒内回应、检索毫秒级）
```

## 二、对话基调（豆包式，无场景预设，通用逻辑）

### 2.1 说话方式（所有对话通用）
- 像朋友：口语化（"得嘞""嗐""说实话"）、适度 emoji、不端着
- 术语翻大白话（"伤官见官"→"跟领导较劲"）
- 从废话抓关键；情绪低落先共情；开玩笑接得住
- 不扮大师、不说教、不故弄玄虚、不编造

### 2.2 通用应对逻辑（不预设场景，LLM 按常识判断）
- 用户说什么就接什么——含糊/反话/跑题/情绪化都自然应对
- 信息不全 → 自然地问（问一个不追问；用户不答就用已有信息）
- 非命理话题 → 照常聊，有机会自然引回
- **无场景模板、无硬编码话术**——所有应对由 LLM 基于上下文即时判断（人是通用来，我们也通用来）

### 2.3 对话流程（每轮固定）
```
用户消息
  ↓
① 系统组装上下文：对话历史(最近5-8轮) + 用户画像(八字/偏好/主题) + 系统引导(说话方式/底线/工具说明)
  ↓
② LLM 判断：先接情绪 → 需要工具？→ 需要就输出 <tool_call>
  ↓
③ 工具执行：查到 → 结果注入（增强回答）；查不到/失败 → 不注入，继续
  ↓
④ LLM 以豆包式语气生成回复（引用古籍或纯对话，风格不变）
```

## 三、检索与来源（可选增强，不影响对话基调）

### 3.0 来源体系（用户 8/8 确认——四类来源，统一角标）

```
① 古籍库（276 万 FAISS）——我们自己的原典原文（docs.db）
② 引擎数据——排盘结果/八字分析（回答引用命盘时的依据）
③ 对话记忆——"上次你说过…"（引用用户历史）
④ 网络检索（新增）——大模型+联网补充（最新资讯/社会信息）
```

- 大模型回答的来源=引擎数据+古籍+记忆+网络——**全部可追溯，不丢任何依据**
- 回答引用引擎数据也标来源（"基于你的命盘：庚午年…"可点开看排盘详情）

### 3.1 数据
```
FAISS 2,760,956 块（bge-m3 1024维，段落级，docs.db 6.46GB，2026-08-05 建）
查询：问题 → bge-m3 编码 → FAISS Top5（<100ms）→ docs.db 取原文
```

### 3.2 检索升级（检索质量批次，待实施）

**查询扩展 + 召回-精排分离（防偏题核心）**：
```
用户原问题
  ↓ 查询扩展：LLM/术语表 → 2-3 个扩展查询（命理术语/同义改写）
  ↓ 召回阶段（找得全）：扩展查询多路召回 → 候选池 Top50
  ↓ 精排阶段（排得准）：⚠️ 用【用户原问题】rerank 打分（bge-reranker-v2-m3，本地已有）
  ↓ 低分片段丢弃 → Top5
```
- **不重新入库**（库不动，只改查询流程加 rerank 步）
- **三道防偏保险**：①精排回原语境（扩展只管召回，相关性以原问题为准）②注入带语境（【用户问】→【相关资料】格式）③prompt 约束（"只引用直接相关的，不相关忽略"）
- **回答后校验**：引用 [n] 与问题主题相似度校验，不相关剔除

**网络检索（联网能力）**：
- AI 判断需要最新/补充信息 → `<tool_call>搜索: 关键词</tool_call>`
- 本地 firecrawl 检索服务（localhost:3002）→ 结果带来源 URL → 注入
- 古籍库（命理专业）→ 记忆（个性化）→ 网络（补充/最新）按需组合
- 网络来源角标点开=网页内容（与元宝一致）

### 3.3 引用交互（统一角标，元宝/豆包式）

```
正文：…古籍里说官星有力主贵人提携 🔗  …根据最新的资讯来看 📎
          统一浅色链接符号（浅朱砂/浅灰，轻微悬浮感）
          不抢正文视线，一看就知道能点

点角标 → 底部抽屉（可上下拖动，半屏↔全屏，墨韵风格）
  ┌ 参考资料 ─────────────────┐
  │ [古籍] 《千里命稿》·论官星   │
  │ [引擎] 你的命盘（庚午年…）  │
  │ [记忆] 你之前说过的…       │
  │ [网络] 某某资讯（URL）      │
  └──────────────────────────┘
点某条 → 新页面详情（古籍原文全文/命盘详情/网页内容）
返回 → 回到对话，抽屉状态保留
```

### 3.4 检索行为（用户确认）
- **查到** → Top5 注入 → LLM 引用增强（"古籍《X》里…"），语气仍是豆包式
- **查不到/失败** → **直接跳过检索环节**，LLM 用上下文继续豆包式对话——可以自然说"这个我帮你看看"，然后基于已有上下文聊（追问细节/共情/给通用性建议/换角度），**绝不冷冰冰说"没查到/不知道"**
- **不使用关键词检索**（纯向量）

### 3.5 查不到时的系统引导（传给模型的补充上下文）
当检索无结果时，系统额外注入引导：
```
（检索未命中，不影响对话。基于用户上下文自然继续：
 可以温和地说"这个我帮你看看"，然后：
 - 基于已有信息给通用性的参考建议（不编造古籍）
 - 或追问用户更多细节（"你具体是什么情况下梦到的？"）
 - 或共情/陪伴式回应
 保持豆包式语气，不要提"检索""资料""系统"等技术词汇）
```

## 五、记忆架构（分层记忆 v4——基于顶级产品深度调研）

> 调研结论：ChatGPT=滚动窗口；Claude Code=触发式 LLM 摘要（<summary>+<memories> 渐进式）；LangChain=增量摘要（近期原文+旧轮摘要）；Mem0/Letta=层次化记忆（工作/短期/长期）；前沿 AFM=三档保真度（原文/压缩/占位）。
> **生产级共识：近期原文保留 + 早期分层摘要 + 长期记忆按需召回——而不是简单滚动窗口。**

### 5.1 五层记忆架构

```
L4 知识库（RAG）     276万古籍向量，可选增强（查到注入/查不到跳过）
L3 长期记忆          结构化画像：八字/偏好/主题/关键事件（TTL 过期）
L2 会话摘要          早期对话增量摘要（滚动渐进式）
L1 滚动窗口          最近 N 轮原文（N 按 token 预算动态计算）
L0 当前轮            用户最新输入
```

### 5.2 组装规则（每轮请求）
```
System Prompt（人设/说话方式/底线/工具说明）
+ L3 长期记忆（按需召回：与当前话题相关的画像条目，非全部）
+ L2 会话摘要（早期对话摘要）
+ L1 滚动窗口（最近 N 轮完整原文，保证当前工作线保真）
+ L0 当前消息
+ 工具结果（如有）
```

### 5.3 L1 滚动窗口（动态，不写死 5-8 轮）
- 按 token 预算动态计算 N：预估每轮 token → 填入尽量多的完整轮次
- 预算预留：输出空间 + 系统指令 + 画像/摘要/检索的份额
- **关键事实保底**：八字/用户明确陈述的关键信息（工作/感情状态等）无论多旧都保留原文，不进压缩

### 5.4 L2 增量摘要（触发式，非每轮）
- **触发条件**：上下文估算超阈值（输入 token 数 + 预留输出 > 窗口阈值）→ 触发压缩
- **流程**（Claude Code 式）：
  1. 拆分：从最新往回累计 token 到预算，之前的为"旧消息"（尾部最近轮次始终原样保留）
  2. 分块：旧消息按窗口 25% 分块（每次摘要调用不超限）
  3. 滚动渐进式：块 N 的摘要带入块 N+1 → 每块产出：
     - `<summary>`：对话要点（用户状态/关键结论/未完事项）
     - `<memories>`：值得长期记住的持久事实（转入 L3）
  4. 新摘要替换旧摘要（摘要的摘要，多级收敛）
- **压缩率目标**：90%+（信息密度提升，防注意力稀释）

### 5.5 L3 长期记忆（结构化 + TTL + 按需召回）
- 类型：`profile`（八字/性别/出生地）/ `preference`（风格偏好/禁忌话题）/ `topic`（关注主题+次数）/ `event`（关键事件：换工作/分手/重要节点+时间）
- 字段：user_id, type, content, confidence, created_at, **ttl**（过时信息过期：如"正在找工作"3 个月失效）
- **按需召回**：不是全部注入——当前问题与哪些记忆相关（embedding 相似度或关键词匹配）→ 只召回相关的
- 冲突处理：新信息覆盖旧信息（状态变化理解，不机械堆叠）
- 隐私：用户可查看/删除/不记录；加密存储

### 5.6 与当前实现差距（要补）
| 现状 | 目标 |
|---|---|
| 最近 5-8 轮写死滚动 | L1 动态预算滚动 ✅改 |
| 无早期摘要 | L2 触发式增量摘要（<summary>+<memories>）🔧补 |
| 画像有但无 TTL/按需召回 | L3 结构化+TTL+按需召回 🔧补 |
| 压缩=简单截断 | 上述完整机制 🔧补 |

## 七、数据存储与资产（对话历史全量留存）

> 用户 8/8 明确：对话历史是**核心资产**——存好用于迭代/分析/模型训练。

### 7.1 原则：运行时压缩 ≠ 存储丢弃
- **喂给模型的上下文可以压缩/摘要（L1/L2）——但原始对话全量落库，一条不丢**
- 压缩是"运行时优化"，存储是"资产沉淀"，两层分离

### 7.2 对话表设计（sessions/messages 结构化）
每条消息记录：
```
user_id / session_id / role(user|assistant|system) / content(原文)
created_at（精确到秒）
intent（LLM 分析出的意图）· emotion（情绪标签）
tool_calls（本轮的 <tool_call> 记录：类型/参数/命中与否）
retrieval_hit（检索命中/未命中/未使用）
model（生成模型/版本——训练溯源用）
disclaimer / 安全事件标记（自伤转介等，合规审计）
```

### 7.3 用途（多场景消费）
| 用途 | 说明 |
|---|---|
| **产品迭代** | 分析用户真实问题分布/卡点/流失点 |
| **话术分析** | 情绪-回复质量关联、哪些回复被点赞/收藏（反馈闭环联动） |
| **训练集构建** | 按质量筛选（高赞/高收藏/评测高分对话）→ 清洗 → 微调数据集 |
| **画像挖掘** | 用户偏好/话题趋势（批量分析，不实时） |
| **合规审计** | 安全事件/敏感内容留痕 |

### 7.4 配套设计
- **加密**：content 加密落库（已落地 AES-256-GCM）
- **索引**：(user_id, created_at) 复合索引（已落地）
- **批量导出**：训练集构建脚本（按条件过滤+脱敏导出 JSONL）
- **隐私**：用户可删除自己的记录（已有 data 删除接口）；训练用数据脱敏（去 openid/个人信息）
- **TTL 策略**：原始数据长期保留（资产）；运行时画像按 TTL 过期（已设计）

## 八、过程体验（顶级架构 v8——基于豆包/元宝/ChatGPT/Kimi 深度调研）

> 调研结论：①流式打字机=行业标配（豆包/ChatGPT/Claude/Kimi 全用）；②**秒回是刻意设计**（"思考=用户流失"，豆包 0.5s 内开始输出，不给思考间隙）；③元宝深度思考=**思考路径侧栏实时显示**（假设/验证/排除）；④停止+重试+异常兜底=标配；⑤前端用 fetch-event-source（POST+鉴权）优于原生 EventSource。

### 8.1 双模式设计（对标顶级产品）

```
模式一 · 秒回流式（默认，对标豆包）
  发送 → 0.5s 内开始流式 → 逐字打字机 → 自动滚动 → 可停止
  用户感知：像真人秒回，无等待感（"思考=用户流失"原则）

模式二 · 思考路径（复杂问题自动进入，对标元宝深度思考）
  判定：多步推理/工具调用/命理深度分析 → 显示思考路径（侧栏/上方小字）
  ┌ 思考路径（逐步点亮）─────────┐
  │ ○ 我在看你的八字…        ✓  │
  │ ○ 查阅古籍中的流年记载…    ✓  │
  │ ○ 结合你的情况在分析…     ●  │
  └────────────────────────────┘
  → 然后流式正文输出
  简单聊天永远只走模式一（不强行造步骤）
```

### 8.2 关键机制（全部对标顶级产品）
- **流式输出（SSE + fetch-event-source）**：
  - POST + JWT 鉴权（EventSource 原生只支持 GET，企业级用 fetch-event-source）
  - 严格处理 TCP 分包/粘包（buffer 拼接不丢字不乱码）
  - 首字延迟目标 <500ms；自动滚动到底
  - **useTransition 低优先级渲染流式**（输入框/按钮/滚动不卡顿）
- **思考路径**（元宝式）：工具调用事件+LLM 思考摘要 → 路径逐步点亮；可折叠不抢视线；完成后保留可展开
- **停止生成**：AbortController 中断 fetch——**前端停止+后端取消**（防止历史缺失和计费不一致）
- **重试**：异常一键重试（保留输入和已输出）
- **连续对话**：不等上一条完成可直接发下一条
- **加载细节**：闪烁光标/空状态提示（对标豆包官网）

### 8.3 异常/特殊/逆向场景全覆盖
| 场景 | 处理 |
|---|---|
| 生成超时（>30s） | 提示"回复较长，正在继续生成…"（不中断）；仍超时 → 可中断+重试 |
| 网络失败 | "网络开小差了" + 重试按钮（保留输入内容） |
| 工具失败 | 不展示技术错误，继续豆包式对话（用户无感） |
| 空回复 | 自动重试 1 次；仍空 → "我走神了，你再说一遍？" |
| 用户连续发多条 | 排队处理，最新优先；旧生成结果不覆盖新话题 |
| 停止生成 | 流式中可点"停止"（中断当前生成，已输出保留） |
| 快速切页/退出 | 生成任务后台取消，回来可继续/重试 |
| 长回复 | 分段渐进显示（先出前段，滚动继续） |
| 语音播报 | 基于最终完整文本（不播半截）；播报中可停止 |

### 8.4 与现有差距（要补）
| 现状 | 目标 |
|---|---|
| "研墨中"三点动画（有） | ✅ 保留为思考态 |
| 回复一次性蹦出（无流式） | SSE 流式 + 打字机 🔧 |
| 工具调用无展示 | 思考小字"正在排盘…" 🔧 |
| 无停止/重试/超时处理 | 全套异常处理 🔧 |

## 十一、实施规划（v7 定稿 · 分阶段）

### 阶段 0：检索接回（🔧 实施中）
- FAISS 276万迁移 D 盘 + faiss-cpu + 检索器接入
- 检索=幕后增强（查到注入/查不到跳过自然对话）
- 纯向量，无关键词；兜底=上下文+引导自然对话

### 阶段 1：记忆架构升级（L1/L2/L3）
- L1 滚动窗口动态 token 预算（替代写死 5-8 轮）+ 关键事实保底
- L2 触发式增量摘要（Claude Code 式：分块滚动 <summary>+<memories>，压缩率 90%+）
- L3 长期记忆结构化（type/confidence/TTL/按需召回/冲突覆盖）
- 验证：超长会话（50+ 轮）下上下文预算可控、关键事实不丢

### 阶段 2：数据资产字段补齐
- 对话表加字段：intent/emotion/tool_calls/retrieval_hit/model/安全标记
- 训练集导出脚本（按质量筛选+脱敏 JSONL）
- 分析查询脚本（情绪/话题/反馈联动）

### 阶段 3：过程体验（SSE 流式）
- 后端：SSE 流式端点（start/step/chunk/done + 工具事件）
- 前端：打字机渲染 + 步骤条（元宝式逐步点亮 ✓）+ 思考小字折叠
- 异常处理全套：超时提示/网络失败重试/停止生成/连续对话/空回复重试
- 验证：首字 <500ms、50 轮压力、断线恢复

### 阶段 4：综合验证
- 全链路 E2E（登录→对话→工具→检索→语音）
- 话术评测重跑（记忆/检索增强后）
- 性能压测（并发/长会话/检索延迟）
- 三版前端同步（simple/fusion）

### 阶段 5：检索升级批次（用户 8/8 确认）
- 查询扩展（LLM/术语表多路召回）
- Rerank 精排（bge-reranker-v2-m3 本地模型，原问题打分，防偏题）
- 网络检索工具（firecrawl 本地服务，来源 URL）
- 来源体系（古籍/引擎/记忆/网络四类，统一角标）
- 引用交互（角标→底部抽屉→详情页→返回保留状态）
- 回答后引用校验（不相关剔除）
- 验证：Top5 命中率（80%→90%+）、防偏题用例（"梦见蛇"不再引面相）、角标交互截图
