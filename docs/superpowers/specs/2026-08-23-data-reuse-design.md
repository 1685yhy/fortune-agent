# 对话数据复用体系 — 设计文档（Spec）

> 2026-08-23 · PM 拍板方案甲（三层快路径 + 数据源统一），补充拍板：解梦/历史对话/命主等**全部存量数据**直读复用；晨笺内容与对话收藏**补服务端落库**。
> 探索依据：`/tmp/data_reuse_explore.md`（5 处出生信息副本根源、对话链路 4-7 次 LLM 成本地图、存量数据盘点清单）

## 1. 背景与要解决的问题

PM 真机反馈三个问题：

1. **档案不直答**：对话问"我的档案"，系统不直查已存数据，反而走古籍检索/记忆/引擎/LLM 全流程，答得慢且泛
2. **页面与答案不一致**：同一出生信息在系统内有 5 处副本，同步规则各不相同（users.bazi_info 无条件覆盖 / persons 默认命主年份守卫 / UserMemory 文件字段级合并 / session_summaries / consultations.chart_data），我的页、今日页、对话答案互相矛盾
3. **全流程重走**：每次询问都重跑引擎 + 古籍 RAG + 4-7 次 LLM 调用，太慢没必要

## 2. 目标与原则

- **问什么，直读什么**：用户问自己系统内已有的任何数据，直读秒回，不重走全流程
- **生成类问答走快路径**：引擎重排（毫秒级确定性）保证新鲜，省掉的是重复的 LLM 调用与 RAG 检索（PM 拍板方案乙：总是重新生成，但过程快）
- **单一事实源**：每种数据只有一个权威来源，页面与对话永远一致
- **红线不松**：鉴权/归属/隐私/会员门控；TA 生辰与取名生辰零落库；解密仅服务端内部；向量库只增不改

## 4. 设计

### 块 1：数据源统一（修根）

- **单一事实源 = persons 默认命主**（relation='self'）
- users.bazi_info 保存规则对齐：对话排盘**不再无条件覆盖**，改为更新默认命主（年份不同也更新，不再另建"命主N"）；bazi_info 保留为展示缓存，写入必须与 persons 同步
- /api/user/profile：生日+四柱**同一来源**（persons 派生），杜绝一接口两来源
- 登录响应补 bazi 字段（出生信息+四柱）→ 前端 globalData.baziInfo 有值
- UserMemory 文件职责不变（偏好习惯），与出生信息解耦
- **老用户自动迁移**：persons 无默认命主但 users.bazi_info 有值的用户，首次请求 profile 时自动补建默认命主，无需用户操作
- 注销清理路径（dao.py cleanup_cancelled_accounts）需覆盖新增表

### 块 2：排盘结果落库

- 新增 `chart_records` 表：user_id + person_id + 排盘 JSON（四柱/大运/流年/神煞/起运，**AES 密文**）+ created_at
- 写入点：对话排盘（_save_bazi_records 路径）、表单排盘接口、今日页生成——统一走一个 DAO
- 读取：重看已排结果（对话追问/我的页/今日页）→ 读最近一条该命主记录，**引擎 0 重跑、LLM 0 调用**
- 引擎确定性：同输入重跑结果一致，缓存结果可直接复用（含真太阳时/晚子时口径标识）
- 红线：仅限用户本人/默认命主；合盘 TA 生辰、取名生辰依旧零落库

### 块 3：存量数据全类型直读

**3a. 意图识别新增"查记录"分类**（在 _route_by_scenario 之前判定）：
- 问档案/八字/时辰 → 档案直读（persons + 已存 chart_records）
- 问解梦/梦 → 解梦直读（consultations intent='dream' 最近 N 条）
- 问历史对话/以前说过 → 会话摘要直读（session_summaries）
- 问签/名笺/灯语/择吉/晨笺/收藏/会员 → 各自记录直读
- 判定规则：关键词表 + 轻量意图匹配，**命中即直读分支，不触发全流程**

**3b. "查记录"工具（工具化）**：给对话 LLM 新增工具 `query_records`（参数：类型 + 可选关键词/时间范围），返回直读结果（服务端解密后）。主分析前 LLM 可主动调用；tool_loop 机制已有，复用。查不到时返回"无记录"（明确区别于"没查"）。

**3c. 缺口补落库**：
- **晨笺内容落库**：新增 `jian_cards` 表（user_id + date + card_json AES 密文 + private_line + created_at）；生成时（_precompute_jian_for）落库，直读"我的晨笺/今早的晨笺"；存量回补：次日生成即自然补齐
- **收藏后端化**：新增 `favorites` 表（user_id + type[chat/jian/qian/ming/lamp] + ref 引用 + 摘要字段 + created_at）；前端收藏/取消收藏改走后端接口；**本地存量首次同步**：小程序启动时检测本地收藏存在且未同步 → 上传导入一次；历史页/收藏页改读后端

### 块 4：问事快路径

- 问事（财运/事业/感情等生成类）路径：引擎重排（毫秒级）→ 画像（UserMemory）+ 已存 chart_records 注入 prompt → **单次 LLM 生成**（主分析）
- 跳过 RAG 预检索；LLM 判定知识不足时经 tool_loop 再查古籍（检索兜底）
- 调用次数：4-7 次 → 1-2 次；目标：深度问事首字 ≤ 10s 内明显改善（基线 main 9.7-16.9s）
- 秒回预生成（现有）、响应缓存（5 分钟）保留不动

### 块 5：测试与验收

- 复用 QA 用例库：AC-CONS-001~005（一致性）、AC-PERF-003（对话首字）、AC-CHAT-007（画像注入）
- **新增用例**（回补 acceptance-cases.md）：
  - 档案直答秒回：问"我的档案/八字"→ 直读不重跑，内容与我的页一致
  - 存量直读逐类：解梦/历史对话/签/名笺/灯语/择吉/晨笺/收藏/会员各一条
  - 重看盘 0 重跑：排过的盘重问 → 秒回且与首次一致
  - 老用户迁移：有 bazi_info 无命主 → 自动补建，页面一致
  - 晨笺落库：生成后可直读，次日仍在
  - 收藏后端化：收藏/取消/列表/本地导入各一条
- 合入后 qa-tester 独立验收（黑盒）+ PM 真机复核

## 5. 非目标（YAGNI）

- 不做跨用户数据（share_entries 匿名分享保持无归属）
- 不做晨笺历史回溯生成（历史无内容的日期不补造）
- 不做本地收藏自动回填后端失败的重试弹窗（静默重试+下次启动续传即可）
- 不改向量库、不动 RAG 检索算法（只改调用时机）

## 6. 风险与约束

- 解密仅发生在服务端内存中，任何新增表存储必须走既有 AES 封装（dao.py 已有）
- 前端收藏迁移期间避免重复导入（favorites 表加导入标记）
- 快路径不得破坏降级模式（无额度时仍走零 LLM 降级）
- 数据库变更需与运行副本同步（禁 rsync --delete；手工补表）
- 开发时段约束：9-12 / 14-18 之外执行
