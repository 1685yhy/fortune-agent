## 零、设计原则（附对标结论）

| 原则 | 落地 | 对标出处 |
|---|---|---|
| AI 优先 | 理解/提取/判断/生成全 LLM；规则只做安全拦截+失败兜底 | 豆包端到端意图 / 元宝两阶段改写 |
| 记忆分层 | 原文→原子事实→画像→摘要 四层，按需召回不塞原文 | 元宝 Hy-Memory L1-L4 |
| 快记慢沉淀 | System1 每轮 1 秒内记事实；System2 后台深加工画像 | 元宝 System1/2 |
| 冲突不覆盖 | 关键身份字段先有先用+冲突确认；决策类用"演化链"记演变史 | 元宝 supersedes |
| 用户可管理 | 「明灯记得你」查看/删除/清空画像（隐私红线） | 豆包左滑删 / 腾讯云 Memory |
| 免费联网 | 智谱 web_search（模型自主决策搜不搜，同"边想边搜"）→DDG→firecrawl 降级 | 豆包边想边搜 / 元宝语义判断 |
| 两级模式 | 快答（速览）+ 精批（深度推演，逐步展示） | 元宝快思考/深度思考、深度研究 |
| 引导追问 | 开场白+推荐问题；回答后自动推荐深化问题 | 豆包兴趣标签 / 元宝推荐问题 |

## 一、总体架构

```
用户输入
  ▼
【阶段1 理解】LLM 单调用 → 结构化 JSON
  {主意图, 附加需求[], 关键事实{gender/身份/关系…}, 缺失信息[], 情绪, 语气}
  ▼
【阶段2 计划】LLM → 执行计划（工具并行清单 / ask_first / 需要搜什么）
  ▼
【阶段3 执行】多路并行（asyncio）| 排盘/紫微/奇门/合婚/解梦/择日/检索/画像/档案/联网
  ▼
【阶段4 综合】LLM → 逐项覆盖全部需求 + 引用自检 + 缺信息追问 + 回答纪律
  ▼
【阶段5 收尾】System1 快记（事实→画像，1 秒级）| 落库 | 引用注册 | 缓存
        ↳ System2 后台：画像深加工（偏好/方向/决策演变链）
```

**删除**：fast path（生日直接判排盘）、关键词截胡（"建议/怎么办/学堂"抢答）、一切"看字猜"逻辑（性别等）。

## 二、五阶段详解（含调研融合点）

### 阶段 1 · 理解（豆包多意图拆解 + 元宝两阶段改写的工程化）
一次 LLM 调用输出 JSON（schema 校验，失败重试 1 次，宽松兜底）：
```json
{
  "primary_intent": "career",
  "secondary_needs": ["bazi", "company_match", "comfort"],
  "facts": {"gender": "female", "subject": "self", "employer": "字节跳动"},
  "missing_info": [],
  "emotion": "anxious",
  "tone": "专业温暖",
  "needs_search": true
}
```
- `facts.subject` 区分本人/他人（帮别人排不污染本人画像）——根治性别 bug
- `needs_search`：LLM 判断是否需要实时信息（公司/行业/时事类=true，古籍命理类=false）——豆包"边想边搜"同构
- 意图体系由 LLM 判定，枚举仅校验不判定；场景不写死

### 阶段 2 · 计划（元宝 Query Planning 简化版）
```json
{"steps": [{"tool":"bazi","parallel":true},{"tool":"search","query":"互联网公司 五行 行业","parallel":true}],
 "ask_first": null}
```
- 缺关键信息 → ask_first 优先追问（不空跑）
- 纯聊天 → 空计划直接综合
- 计划校验失败 → 降级单检索，不崩

### 阶段 3 · 执行（多路并行）
- asyncio 并发；总耗时=最慢一路（排盘 21s 与联网/检索同时跑）
- 每路返回 {ok, data, unavailable_hint}；失败如实标注注入综合（不静默）
- 联网降级链：智谱 web_search → DuckDuckGo → firecrawl → "实时信息暂不可用，以下按命理知识分析"

### 阶段 4 · 综合（回答纪律 + 完整性自检 + 语气）
- 逐项覆盖需求清单（主意图+每个附加需求；输出前 LLM 自检"有无遗漏"）
- 引用仅在直接相关时用（豆包答案级引用：句子挂角标）
- 缺信息礼貌追问；禁油滑开场；禁无关展开（名人对照除非用户问）
- 结合画像自然带出（"你之前在字节工作，结合这个看…"）
- 两级模式：快答（速览）首答 + 自动附"精批"入口（元宝深度研究同构）

**语气（用户定稿，2026-08-09）**：
- **不做任何预设/选择机制**：无语气档位、无选择界面、无"以后都这样"提示
- 系统天然就是**豆包式温和**（人设自然流露，非"预设档"）
- **口头临时调节**：用户说"你严肃点""直接点""别那么啰嗦"→ LLM 理解语气调节指令（非关键词匹配）→ **当前对话临时调整语气**，说完自然回归豆包式，不持久化、不询问

### 阶段 5 · 收尾（System1 快记 + System2 深加工）
- **System1**（每轮，1 秒级）：facts → 画像条目（原子事实，不塞原文）
- **System2**（后台异步）：画像深加工——常问方向/偏好/信任派别；**决策演化链**（用户反复问"要不要跳槽"，立场变化串链）
- 关键字段保护：先有先用/冲突必确认/subject 隔离
- 落库（加密）/引用注册/缓存

## 三、长程记忆与画像（四层，对标 Hy-Memory 简化版）

| 层 | 内容 | 更新 | 使用 |
|---|---|---|---|
| L1 原文 | 会话记录（加密） | 每轮 | 仅最近 N 轮进上下文 |
| L2 原子事实 | "用户：女 1990 年生 已婚 关注事业亲子"（LLM 提取） | System1 每轮 | 相关召回注入 |
| L3 画像 | 常问方向/偏好/信任派别/忌讳 | System2 异步 | 新会话自动挂载 |
| L4 摘要 | 超长会话滚动摘要（LLM） | 触发式 | 替代裸截断 |

- **演化链**：同一主题多次咨询，结论+用户反馈串链；下次解读带演变史（"您上个月倾向跳槽，这次更看重稳定"）
- **时效**：条目默认 180 天，超期降权清理（用户可改）
- **用户管理**：「明灯记得你」——查看全部条目/逐条删除/一键清空/聊天中说"忘掉X"（豆包三件套）
- **隐私红线**：画像加密存储；"体验优化"开关**默认关闭**（默认不用用户数据优化模型，元宝做法）

## 四、免费联网搜索（模型自主决策，不买付费 API）

| 层 | 方案 | 成本 | 触发 |
|---|---|---|---|
| 1 主 | **智谱 GLM web_search**（glm-4-flash 免费 + 现有 key） | 免费 | 阶段1 needs_search=true 时挂 tool，模型自主决定搜不搜/搜几轮（边想边搜同构） |
| 2 备 | DuckDuckGo 免费库 | 免费 | 1 失败时 |
| 3 备 | 本地 firecrawl（Docker） | 免费 | 2 失败时 |
| 兜底 | 明说"实时信息暂不可用" | — | 全失败，不静默不编造 |

- **答案级引用**：每条联网结论句子挂角标+来源（豆包/元宝同构）
- 引用池与古籍引用统一编号（前端已有抽屉）

## 七、实施计划

| 阶段 | 内容 | 依赖 |
|---|---|---|
| P1 | 管线骨架：理解 JSON（删 fast path/关键词截胡）、计划、并行执行、综合纪律、System1 钩子 | message_analyzer/handler/tool_calls/prompts |
| P2 | 记忆升级：四层+原子事实提取+画像深加工+演化链+关键字段保护（性别 bug）+「明灯记得你」管理接口 | memory/ 新模块+api |
| P3 | 免费联网：智谱 web_search 接入+DDG 备+降级链+答案级引用 | 新 search 工具 |
| P4 | 前端联动：引导、多人档案（排盘选命主）、对话历史、画像管理（配合原型） | 三版前端 |
| P5 | 交互增强：追问推荐升级、两级模式（精批）、对话接力 | 前端+后端 |
| P6 | 名人库按确认项处理（A 移除 / B 限场景） | handler/advisor_v2 |

每阶段独立可上线；P1 完成即可明显改善"只理解一个/跑题"。

## 八、验证策略
- 每阶段单测：理解 JSON（30+ 场景）、计划、画像提取/保护（性别 6 例）、演化链、降级链
- 回归：test_ai_native 全组 + test_auth/gap_api/virtual_pay 不破
- 真实 E2E：5 组实测（多意图/帮他人/纠正性别/缺信息/联网问题）比对前后输出
- 上线：本地重启生效 → 体验版复测
